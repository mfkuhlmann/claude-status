# Changelog

## Unreleased

- **Talpa, a new pet of its own:** Clawd is gone. Talpa lives in a burrow: it stays half underground while it works and plays, digs over to another spot (towards your mouse) instead of walking, and only comes all the way out when you drag it out; dropped, it digs back in where it landed. A new chat's pet digs up out of the ground, and one whose chat leaves the list waves and digs away. Its lamp glows in the chat's state color, and it picks what to do at random from what fits the moment (typing, thinking, hunting bugs, checking tests, juggling subagents, calling you with a sign or a phone, sleeping, sneezing itself out of its burrow, balloons, peekaboo, …), so it's never the same twice. A chat's pet wears a calm version of the chat's color. It's one creature, drawn by the same code in the Plasma widget, the GNOME extension and the VS Code extension: it moves fully on every Plasma version now (no QtQuick.VectorImage module needed), and on GNOME too.
- **A new panel icon:** Talpa peeking up through the panel's edge, in the state color: it pops up when a chat needs you, glances around while Claude works, smiles when it's your turn and sleeps when nothing runs. The notifications show Talpa too.
- **Chats in a steady order, pets too:** an account's chats that need you come first (the one asking longest first), the others in the order they started, the newest last; a row no longer jumps around while its chat works, idles or finishes. Its pets stand left to right in the same order, and when a new chat comes the others hurry over to make room. The bar in the pet's color next to each chat is twice as wide, so you find a pet's chat at a glance.
- **Lighter on the CPU:** only the big Talpa is drawn all the time, and only as often as that shows something new (25 times a second while it moves quickly, 5 while it just breathes). A chat's pet shows pictures, drawn only when what it shows changes: each pose of what it does fades over to the next, quick moves (typing, waving, bouncing) go back and forth between two pictures, and it still blinks and looks around; while you hold it, it's drawn live. All pets of a dashboard run on one clock, and not at all while scrolled out of view. The stage's glow (a chat needs you) and its stars pulse in steps instead of redrawing the whole dashboard 60 times a second.

Fixes from a review of the whole code:

- **Tasks and plans sent to VS Code arrive whole:** a task or plan given to VS Code's Claude was cut at its first `&` (*Run make && make test* arrived as *Run make*), a `+` turned into a space, and a subagent run named like *Port C++ parser* didn't open there. VS Code decodes a link once before the extension reads it; the widget's links now take that into account.
- **Memories and `CLAUDE.md` open in VS Code:** with **Open plans and runs in** set to VS Code they didn't open at all (the extension's preview takes only plans and runs); they open in VS Code as files now.
- **Feedback on a plan** whose chat is open on another account (a shared chat) started a second copy of the chat in a new terminal: it brings up the open one now. Where Claude had deleted a line of the plan, the feedback reported a blank line you never wrote, and long feedback in a non-Latin script didn't reach the chat.
- **Tasks:** a one-word task such as *update* or *doctor* ran that Claude command instead of starting a chat about it. A task about a long plan didn't start in a terminal on an SSH host: the plan is now cut, at a line's end, to what fits, and the prompt says the rest is in its file. A task or chat waiting for a weekly limit said only the time it starts, not the day.
- **States:** a background session you had answered whose process then died said *Needs input* for good; after `claude --resume`, the subagents of the chat's earlier process showed as still running; a failed check's error stayed up to 30 s after the checks worked again.
- **Accounts:** **Remove** took what other accounts link to in the account's folder (settings shared from it, a `projects/` folder shared through a link) to the Trash with it, which broke those accounts: it now refuses and says what links there, and also while something is mounted inside the folder. **Make Default** could point `~/.claude` at the wrong folder for an account kept outside your home folder. A second line in an account's name file broke its `claude-NAME` command. The Accounts settings showed no message any more once you had closed one, and a failed list's error stayed after the list worked again.
- **VS Code's settings are kept as they are** when its account is switched: a comma inside a string value was dropped (so another environment variable could change), a `settings.json` starting with a byte order mark read as having no account, Windows line ends became Unix ones, and a `settings.json` that is a link (to your dotfiles) was replaced by a plain copy.
- **Keep only on …** could delete a chat's only transcript when one account's `projects/` folder is a bind mount of another's.
- **SSH hosts:** a VS Code chat on a host whose window was connected by the host's address (its HostName) wasn't brought up; a Konsole tab whose ssh was started as `ssh -Xp 2222 host`, or with a user name containing `@`, wasn't found. A host shown again notified limit resets and **⚠ same files** from while it was hidden; its memories showed the host's own time, and its limit resets in the away summary didn't name it. Where a host's plan usage shows under another computer's account, **Continue on …** and waiting for the limit ignored that usage.
- **Usage:** a shared chat stopped by another account's limit marked this account's plan window full; one status-line snapshot vanishing during a check hid the account's limits; a chat shared after it was read counted its earlier tokens as not shared; token counts said *1000.0k* just below a million.
- **Lists and search:** a found chat's dot was green while its row's was red; a stale SSH host's error ran into *Showing what it said*; a chat open on two accounts got two pointer lines on a third account and was named twice in **⚠ same files**; memories didn't open when an account's `projects/` folder is a link; a plan's **Carry it out** box rebuilt while its list was open showed an empty task field (the chat would still start with the task).
- **Pets:** a chat's pet never heard that its usage limit had reset (it kept its low-battery pose and *resets in <1m*); a pet held while the popup closed stayed up in the air; a pet whose chat left showed the on-call sign instead of waving goodbye.
- **Smaller fixes:** one process with a long non-ASCII name broke switching to Konsole tabs and VS Code windows; a failed cache write (e.g. on a full disk) left a temporary file behind at every check; desktop notifications were kept in memory until Plasma restarted; a setting changed in one copy of the widget reached the others up to 30 s late; a closed copy of the widget stayed the one that notifies after the clock was set back. The page a plan or run opens as in your browser broke links whose address has `_` or `*`, turned the rest of a plan into code after a fence like ```` ```python title="x" ````, and dropped the `#` of C# in headings. **Compare in VS Code** showed a file whose earlier version Claude had removed as empty before the chat.

## 1.13.0 (2026-10-21)

- **Wait for the usage limit:** when an account is at its usage limit, a task in the **+** box with **In the background** can wait: **After the limit resets** queues it under the account (in a recent folder, or **Choose folder…**), and it starts in the background a minute after the limit resets (as soon as the widget runs, if it didn't then). The account lists its queued tasks, with when they start: start one now or cancel it. One that can't start (e.g. its folder isn't trusted any more) stays, saying why. Also for SSH hosts' accounts (they start from here, over ssh).
- **Queued tasks wait for the limit:** a task (or a chat going on by itself) whose account is at its usage limit when its time comes waits on, and starts a minute after that resets, instead of stopping at once; **Start now** still starts it right away. A chat that went on by itself keeps its name (Claude named its background session after the message it went on with).
- **Start a background task later:** under **In the background** in the **+** box, **Later:** picks a day (today or one of the next six) and a time; the task waits under the account and starts in the background then (as soon as the widget runs, if it didn't then). The account lists it with when it starts: start it now or cancel it. Unticked, a task starts right away, as before. Also for SSH hosts' accounts.
- **Chats go on by themselves after the limit:** a chat a usage limit stopped gets **Go on at 10:41** next to **Continue on …**: a minute after the limit resets, it goes on in the background with *The usage limit has reset: go on where you stopped.* (`claude --bg --resume`: the same chat). An idle Claude that still has it open quits first (a background session is stopped); if the chat went on before then, nothing happens. It's listed with the queued tasks (click the button again, or ✕, to cancel). In **Recent chats**, click a chat's red **limit** tag. Only in folders Claude trusts (as for background tasks). Also on SSH hosts.
- A chat's **Go on at …** and **Continue on …** buttons opened the chat's summary instead: the line's click area lay over them.
- **A background session the limit stopped** said *Needs input* (Claude marks it as blocked, *rate limited — wait and retry*): it now says **Limit · resets in …** like the others, and doesn't count as needing you.
- **The summary counts chats at the usage limit apart:** *1 working · 2 at the usage limit* (red), instead of counting them as idle or done (one whose process is still there, one whose background session was stopped).
- **Finding more than chats:** the search also finds project folders (by their path: click one for a new chat there), plans (by their title or text) and memories (by what they say), listed first, before the chats. Each kind folds under its heading (**Memories (9)**, **Chats (26)**), and so does each computer: the chats show at first, the rest too when no chat has the words; **Unfold all** shows everything.
- **Each account's memories:** what Claude keeps about you and your projects (its notes in `<config>/projects/<folder>/memory`) is listed under each account (**Memories**, folded), after the account's own `CLAUDE.md` (your instructions for every chat on it; marked when it's one file shared between accounts), newest first: what each says, its kind (user, feedback, project, reference) and the folder it's for. Click one to read it rendered; the edit button opens its file, to change what Claude remembers. An SSH host's open in VS Code (Remote - SSH).
- **Feedback on a plan, to the chat that made it:** change the plan's file (✎), writing notes into it where you like, and the chat gets a **↩ send to Claude** tag (each plan's row a send button): your changes go to the chat, which revises the plan in plan mode. What you changed is told apart from what Claude wrote by Claude's own version, rebuilt from the chat (what it wrote to the file and its edits since), so Claude gets exactly your changes. A chat in tmux gets them typed in; one open elsewhere gets them on the clipboard and comes up, to paste them there (if Claude asks whether to go ahead with the plan, choose to keep planning first); one that isn't open reopens in plan mode with them. A plan you changed keeps its chat (it was lost from the list once the plan was newer than its chat).
- **Edit a plan:** a **✎** next to a chat's **plan ↗** tag, and in each plan's row, opens the plan's Markdown file to change it: in your app for Markdown files, VS Code when the settings open plans there, or your app for text files when Markdown opens in Okular (which only shows it). An SSH host's plan opens on the host in VS Code (Remote - SSH). Plans open to read, rendered, as before.
- **The whole folder on hover:** a chat's folder, and those of recent chats and plans, are often cut short; hovering one shows all of it.
- **Two chats changing the same files:** chats that are open and changed some of the same files get a red **⚠ same files** tag naming the other chat and the files (click it to go there), and a notification when it starts: two chats editing one file can overwrite each other's work. Also on SSH hosts.
- A background chat shared with another account, then kept only there (**Keep only on …**), came back under the account it ran on, as a stopped background session, for a day (Claude keeps that account's record of the session): it's now only on the account that kept it.
- **Plans and subagent runs open rendered:** in Okular where it's installed (it shows Markdown), else as a page of their own in your web browser (made by the widget, nothing loaded from the internet), instead of your text editor. The settings' **Open plans and runs in** can pick Okular, your browser, VS Code's Markdown preview (with the Claude Status extension for VS Code 1.13 or newer) or your own app for Markdown files.

Meanwhile **Continue on personal** moves the chat to another account with room left in that limit: shared with it, then reopened there in a terminal. An idle Claude that still has the chat open here quits first; a chat in VS Code's Claude tab, close it there first. A chat whose login expired says so too.

While nothing was said after it, the line under the chat shows it instead of Claude's last words, and the chat's unfolded box starts with it. Recent chats show theirs in their tooltip.

Click a folder and the chat starts with it: in a terminal (sent right away), in VS Code (typed into a new conversation, for you to send) or, with **In the background**, as a background session (`claude --bg`): no window opens, and it's listed right away, so you see when it needs you. The background only works in folders Claude trusts already (it can't ask there), so never in your home folder. Ctrl+Enter starts it in the first folder. Also on SSH hosts.
- **Find a chat:** the magnifier at the top of the popup looks through all your chats, on this computer and on the SSH hosts shown: every chat with all the words you type in its name, its folder or one of your prompts, newest first. - Background sessions open, stop and start even with `CLAUDE_CODE_DISABLE_AGENT_VIEW` set for your whole desktop: Claude refuses `attach`, `stop` and `--bg` while it's set, so these commands now run without it. A background session the widget starts runs in a systemd scope of its own, so restarting Plasma doesn't end Claude's background service.

The widget never sees a login, and neither runs while chats use the account. A new account shows up before its first chat.

Not while it would cut a chat off: one working in VS Code's Claude, or any Claude running through the name `~/.claude`. The default is VS Code's Claude's account where VS Code is, else plain `claude`'s; the page says when the two differ.

- **Log in…** in the popup for an account that isn't logged in (a new one, or logged out), also on an SSH host (Claude's login there over ssh: you paste the code it gives you). Its old plan usage isn't shown.
- **A new chat on an SSH host's other account opens in VS Code too** (Plasma): VS Code's Claude on that host switches to the account first and stays on it (in the settings of the host's VS Code server, which windows connected to it read: only that entry changes, a file's comments and other settings stay). The VS Code extension does the same for its chat tab, and its account item works in Remote-SSH windows.
- SSH hosts: which account VS Code's Claude uses on a host now comes from its VS Code server's settings (the host's `~/.claude` was assumed), so the right account gets the VS Code tag and comes first.
- **An account's plan usage shows once** (Plasma, VS Code): an account logged in on this computer and on an SSH host (or on two hosts) has one plan usage, which showed under each copy. It now shows where the account is listed first, with the newest numbers of them all (it says which machine they come from when it's another one). *Plan usage on SSH hosts* in the settings shows each host's own again, or none on hosts.
- VS Code: the status bar's 5-hour usage is that of the account VS Code's Claude runs on (it was the account with a running chat, so a terminal chat on another account showed that one's).
- Plasma: a new chat in a terminal on an SSH host did nothing (since 1.6): clicking a folder closed the list, which took the folder's row away in the middle of its click, and the rest of it never ran.
- The account VS Code's Claude uses is listed first (it was the one `~/.claude` points to, which a switch in VS Code's settings doesn't change). On every front end.
- SSH log in: through a jump host (`ProxyJump`), the connection dropped as soon as the login window closed, so the next check asked for the password again; the connection to the jump host now stays too (checked with real OpenSSH). The login's marker file is private.
- **Plan usage of an account you use in VS Code:** VS Code's Claude panel runs no status line, so such an account kept the numbers of its last terminal chat (a day old, say) and the panel icon showed the other account's. The widget now also reads Claude Code's own cache of the plan usage (`cachedUsageUtilization` in the profile's `.claude.json`, what `/usage` and the panel fetch) and shows whichever is newer. On every front end.
- **SSH hosts that want a password** (Plasma): such a host shows **Log in…**, which opens a terminal where `ssh` itself asks for the password (or passphrase, one-time code, new host key). The widget never sees or keeps it; the checks go through the connection that login opened, until 30 minutes after their last check, until you log out, or until you click **Disconnect**. That connection forwards neither your agent nor X11, whatever `~/.ssh/config` says, and host keys are checked as always. The GNOME and VS Code extensions keep their texts for now (`remote.py --login HOST` is there for them).
- *Recent chats* start folded on SSH hosts too, like on this computer, so the popup is short after a restart or login. Both on Plasma and GNOME.
- **Several copies cost about as much as one** (Plasma): the panel, the tray and a dashboard on each screen's desktop share one status check instead of each running its own every 2 s (and one check per SSH host), a check that says what the last one did (but for the time) doesn't rebuild the dashboard, and on the desktop the pets and the spinner rest while a window covers the whole widget (as Plasma's animated wallpapers do). - **Checks cost about 40% less** (Plasma, GNOME, and VS Code once its copy of the backend is updated): Python compiled all of `claude_status.py` on every check; the widgets now start it through `poll.py`, which keeps the compiled code in `~/.cache/claude-widget/pycache` (Python 3.8 or newer; nothing is written into the installed widget).
- **Says when Claude Code writes something new:** the widget reads files Claude Code doesn't document, and a session status, session kind or background-job state it doesn't know used to count as idle, or hide the chat, without a word. The popup now names the new values and the Claude Code version that wrote them, so a wrong state doesn't go unnoticed until the widget is updated. On every front end.
- Plasma: a dashboard on the desktop froze its pets after you opened a chat (or its changes) from it, until plasmashell restarted: opening something "closed the popup", which a dashboard on the desktop doesn't have.
- **A chat in VS Code's terminal comes into view** (Plasma, GNOME): clicking it raised VS Code's window, but a terminal panel you had closed stayed closed, and another terminal could be the one showing. With the Claude Status extension for VS Code (1.11 or newer) the chat's own terminal now comes up, the panel too. Also on SSH hosts, for a chat in the terminal of a VS Code window connected to the host (Remote-SSH): that click looked for a terminal tab with an ssh connection to the host, so it showed an unrelated one or said there was none.

## 1.10.1 (2026-10-19)

- **Share chats on SSH hosts:** a host with two or more Claude accounts gets the share button too, on its finished and recent chats: **Continue on work** shares the chat with that account there and reopens it in a terminal over ssh, **Share with all accounts** and **Keep only on …** work as they do here, between the host's own accounts. Nothing is installed on the host: the sharing script goes over the ssh connection like the status script, and the shared chats' folders are in the host's `~/.local/share/claude-status`.
- The GNOME extension has no share button, and the VS Code extension gets the same.

Fixes (from a review of the whole code):

- **Keep only on …** could delete a chat's only transcript when two accounts share one `projects/` folder through a link; it now never removes the copy it keeps, checks the disk before moving anything, and takes back what other accounts left in the share store.
- SSH hosts: a host's answer was read from the last line of its output, stderr included, so a shell warning on the host (e.g. about a missing locale) made a refused share, stop or removal look done; the answer comes from stdout now. A chat whose text mentions the widget's answer marker no longer breaks the whole host, a login greeting that isn't UTF-8 neither. A host's own `RemoteCommand` (e.g. starting tmux) and port forwards from `~/.ssh/config` are left out of the widget's connections, its commands run in `sh` whatever the login shell is, and a check that's given up on ends its ssh too. `# comments` in `~/.ssh/config` no longer make hosts up, and an `Include` inside a `Host` block no longer ends that block.
- After switching the `~/.claude` link, a new or resumed chat of an account could open on the other one; it now uses a name that still leads to its account.
- Half an emoji in a chat's title (or anything else that can't be written as UTF-8) made every check fail; the status is written as ASCII JSON now.
- A shared chat could be hidden as "moved on" when a copy of it was open somewhere; a chat that moved on to a listed session no longer shows under *Recent chats* too.
- Subagents that ended on an API error (e.g. a usage limit) or were interrupted showed as *running · writing…* until their chat ended: they show as *failed* (in red) or *stopped*, and one Claude marks as finished is done. A fork no longer counts the call that started it (its parent's reply and tokens) as its own work, and an agent the chat sends more work shows as running again.
- Several copies of the widget (panel and tray, the GNOME or VS Code extension) no longer throw away each other's cache entries and token caches, which made them read big transcripts from the start again; a copy with other settings no longer forgets your removed sessions either, and removing one while a check runs isn't lost.
- An old copy of a background session's record (left behind by a link switch) could show as *needs you* forever; one odd record or status-line snapshot no longer hides all of an account's background sessions; one odd transcript line no longer empties *Recent chats* or the token totals.
- Two profiles of one account sharing a chat counted its tokens twice. The 1-hour usage forecast now takes the real time since its last point; a clock set back no longer stops token scans; snapshots are pruned with token totals off too.
- Plasma: chat names, agent activity and other text from transcripts are shown as plain text (as rich text, an `<img>` in an agent's activity made Plasma fetch it); notification texts are escaped. Clicking a *Couldn't open* notification opens the popup instead of another error; a failed action on an SSH host notifies when the popup is closed. A host that stopped answering no longer keeps the badge, tray status and shortcut busy with its old chats, and unticking a host forgets them (no burst of "finished" when you pick it again). A host's clock being off no longer skews its times. A chat's notifications and "seen" follow the chat, not its row: a background session whose row changes from running to finished still notifies, and one listed twice no longer alerts every minute.
- Plasma: the usage bars (and their forecast tooltip) no longer rebuild every check; the settings dialog no longer puts back hosts or the VS Code switch changed in the popup meanwhile, shows the phone you picked, and the volume slider goes in whole steps; the icon stops pulsing once you've opened the popup; hosts picked together are all checked at once; no Interrupt for a chat whose turn is over.
- Pets: a pet turned around mid-walk no longer walks on looking like it stands still, a chat's pet no longer vanishes without walking off, one grabbed while falling or leaving behaves, and they keep their spots when the list changes; no particles pile up while the popup is closed; same chat on two accounts, two pets; less work per check.
- GNOME: the "while you were away" notification was closed right after it showed; a hung check no longer stops the checks for good; a failed start leaves nothing behind; the shortcut needs a modifier key; and the same fixes as on Plasma for hosts, notifications and agents.
- `install.sh`: the "add the snippet by hand" hint now shows when no status line is found; status lines run as `bash $HOME/…` or without `.sh` are found; the script is replaced in one step (Claude never runs it half-written), with a clear message when it can't be written; GNOME Shell 45–48 are refused before anything is installed; `--uninstall` keeps the snippet while another front end uses it. The snippet itself can no longer stop a status-line script that uses `set -e`.

## 1.7.0 (2026-10-18)
